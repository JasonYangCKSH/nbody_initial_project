# Collision Lab：寬相碰撞偵測互動 DEMO

以瀏覽器即時展示粒子系統的 **Broad-Phase 碰撞偵測**，比較暴力法、均勻網格（Uniform Grid）與八元樹（Octree），並視覺化 **Verlet List 的 skin 機制**：skin 依粒子瞬時速度與加速度動態計算，並受空間結構的幾何上界限制。

本 DEMO 對應專題論文〈異質動態粒子場景下整合八元樹空間分割與 Verlet List 自適應更新之碰撞偵測〉。論文的實驗數據由另一份 C++ 實作產生，這個 DEMO 用來直觀說明同一套機制在做什麼。

## 快速開始

需要 **Node.js 20.19 以上或 22.12 以上**（Vite 7 的要求）。

```bash
npm install
npm run dev
```

打開終端機顯示的網址（預設 `http://localhost:5173/`）。

其他指令：

| 指令 | 用途 |
|---|---|
| `npm test` | 執行單元測試（Vitest） |
| `npm run build` | 型別檢查並建置正式版到 `dist/` |
| `npm run preview` | 預覽建置結果 |

## 核心概念與對應程式

| 概念 | 說明 | 程式位置 |
|---|---|---|
| 暴力法 | 所有粒子兩兩比對，O(n²)；作為正確性基準 | `src/core/spatial/BruteForceStructure.ts` |
| 均勻網格 | 固定大小的格子，只比對相鄰格子；skin 上界為 `cellSize / 2 − r`（論文式 3） | `src/core/spatial/UniformGridStructure.ts` |
| 八元樹 | 格子內粒子超過容量就切成 8 格，密集處切得更細；skin 上界為 `葉節點半邊長 − r`（論文式 4） | `src/core/spatial/OctreeStructure.ts` |
| 動態 skin | `skin = K·|v|·Δt + ½·|a|·(K·Δt)²`（論文式 1） | `VerletBufferController.computeSkin()` |
| 重建判定 | 任一粒子自上次重建起的累積位移 `Δx > skin` 就重建（論文式 2） | `VerletBufferController.isListValid()` |
| 一步模擬流程 | 判定是否重建 → 寬相 → 窄相 → 碰撞回應 → 積分（論文圖 2） | `src/core/SimulationRunner.ts` 的 `step()` |

播放速度只改變「多久跑一步」，每一步的物理時間 `dt = 1/60` 固定，所以結果不受播放速度影響。

均勻網格的格長固定為兩倍直徑（`cellSize = 2 × 2r`，半徑 0.075 時為 0.3），換半徑時格長會跟著變，否則相碰的兩顆球可能隔兩格而漏抓。

## Demo 劇本（一鍵套用）

側邊欄最上方三個按鈕，一按就套好全部設定，暫停在第 1 幀，畫面中央顯示「按這裡開始播放」。設定在 `src/presets.ts`。

| 劇本 | 內容 | 主要設定 |
|---|---|---|
| 劇本一：Verlet list 概念（進入頁面時的預設） | 少量大球、慢動作；候選配對同色並連線；兩顆焦點球（黃色光圈）約第 25 幀變成候選配對、第 37 幀正面相撞並反彈 | 小空間邊長 8、35 顆、半徑 0.35、等速、八元樹、K = 12、0.5× |
| 劇本二：方法比較 | 上下兩個同步畫面、同一批粒子：上均勻網格、下八元樹；並排顯示重建次數、候選配對數量、偵測時間；畫面上可即時調整 K、切換均勻／群聚、開關加速度 | 邊長 25、3,000 顆、半徑 0.075、群聚 0.6（3 處）、加速度 0.5、K = 12 |
| 劇本三：八元樹結構 | 粒子少、葉節點容量 6；各層不同顏色，葉節點實線、已切開的格子虛線；鏡頭自動旋轉 | 邊長 12、150 顆、群聚 0.7（2 處）、葉容量 6、最大深度 5 |

劇本二的上下兩邊找到的碰撞完全相同（單元測試確認兩者都和暴力法一致），所以粒子運動一模一樣，差別只在找候選配對的成本。

## 功能

### 碰撞與重建的視覺化
- **候選配對上色**：同一組候選配對（相連的配對算同一群）用同一顏色並畫線連起來，10 色色盤，附近的群組盡量不同色；不在名單裡的球是灰色。名單只在重建時改變，所以重建時顏色會整批換掉。
- **碰撞標示**：碰撞的球先閃白光、維持碰撞色，約 1.2 秒後淡回原色，接觸點加上向外擴散的光環；暫停在碰撞那一幀時標示會一直保留。
- **重建提示**：重建那一幀在畫面上方出現「第 N 次重建：全部粒子一起重新找候選配對」，寫出觸發的球與這一幀的偵測耗時；重建次數會跳動。
- **觸發粒子定位**：最近觸發重建的粒子（超出自己 skin 最多的那顆）標成紫色，並加上圓環、光柱與 skin 線框球。
- **八元樹切割畫面**：依層級上色；層級清單列出每層的邊長、葉節點數與已切開數；可多選層級，可用虛線顯示已再切開的格子，也可只顯示選取層級的粒子。
- **粒子資訊面板**：點擊粒子或重建記錄即可查看位置、速度、加速度、skin、skin 上界、累積位移（佔 skin 的比例）、所在葉節點的層級與大小、格子容量與觸發重建次數。

### 數據面板
- **重建次數**放最顯眼的位置，旁邊寫出目前共幾幀、其中幾幀重建。
- **效率指標**：碰撞偵測時間（判定 + 寬相 + 窄相）與距離比對次數（寬相 + 窄相，沿用名單的幀只有窄相），附近 60 幀平均與每幀偵測時間長條圖（紫色是重建的幀）。
- **配對**：候選配對數量（Verlet list size）、實際碰撞數。
- 劇本二改成兩欄並排，較少的數字標綠色，並寫出兩邊偵測時間的倍數。

### 場景
- **小空間**：少量大球在盒子裡等速運動，第 0、1 顆是安排好會正面相撞的焦點球。
- **粒子雲**：均勻或群聚分布，可調整群聚程度與群聚中心數。
- **煙火爆炸**：1～8 發煙火在空中不同位置炸開，快慢不一的火花受重力落下；夜空、星星、草地，炸開時照亮地面。同一個場景同時呈現**密度異質**（中心極密 → 逐漸散開）與**速度異質**。

### 操作
- 播放／暫停、**上一幀**（劇本一最多保存最近 300 幀，粒子多時自動減少）、**下一幀**、從頭開始；可勾選「碰撞時自動暫停」。
- 播放速度 0.25×～4×，顯示目標與實際每秒幀數。
- 配色：預設「樸素」（格線單色，只有候選配對與重點標示有顏色），可切換回原本的「彩色」。
- 手動調整的參數都在「自由調整（進階）」裡，預設收合。
- 中英文介面切換（預設中文）；手機版畫面在上、面板在下。
- 鏡頭對準選取的粒子、重設視角、自動旋轉視角。

| 場景 | 按鍵／滑鼠 | 作用 |
|---|---|---|
| 粒子雲 | W/A/S/D、Q/E、Shift | 移動鏡頭、上下、加速 |
| 粒子雲／煙火的自由視角 | 拖曳滑鼠 | 旋轉場景 |
| 煙火 | W/A/S/D、Q/E、Shift | 觀眾走動、轉向、跑步 |
| 煙火的觀眾視角 | 點一下畫面 → 移動滑鼠 → Esc | 鎖定滑鼠、轉動視角（Minecraft 式）、放開滑鼠 |

煙火場景的「阻擋者小遊戲」沒有放在 `main`（也就是線上網站）上，保留在 `feature/blocker-game` 分支，之後需要時再合併回來。

## 建議的演示流程

1. **劇本一**（進入頁面就是）：按播放。灰色的球不在候選名單裡，同色並連線的是候選配對；紫色球走出自己的 skin 時畫面上方出現重建提示、配對顏色整批換掉。兩顆黃色光圈的焦點球先變成同色配對，接著正面相撞並反彈。可勾選「碰撞時自動暫停」，或用上一幀／下一幀逐幀說明。
2. **劇本二**：上下兩個畫面同一批粒子。看並排數據：八元樹重建次數較少、候選配對較多。拖動畫面下方的 K，觀察兩邊差距怎麼變；切換「均勻／群聚」比較兩種分布。
3. **劇本三**（選用）：鏡頭自動旋轉，說明八元樹在密集處切得更細（深層小格）、稀疏處停在淺層大格。

## 測試

```bash
npm test
```

共 24 個測試，涵蓋：均勻網格與八元樹的候選配對和暴力法一致；**開啟 Verlet 緩衝後每一步找到的碰撞都和暴力法完全相同**（每顆粒子 skin 不同、碰撞後改變方向也一樣）；沿用名單的幀只算窄相的距離比對；skin 上界、格長跟著半徑變；八元樹密集處會切到最大深度（與 C++ `Octree::split` 一致）；碰撞回應；八元樹的葉節點與層級資訊；小空間的焦點球先變成候選配對再互相碰撞；上一幀倒回後再往前跑，結果和原本完全一樣；爆炸場景與聚集數量。

## 已知限制

- 模擬在瀏覽器主執行緒上計算；粒子數上萬時使用暴力法，每一步可能要數秒，期間畫面無法操作。
- 八元樹找候選配對時會比較每一對葉節點是否重疊，而且外擴距離取「全場最大的 r + skin」（與 C++ 版本相同）。群聚場景裡只要有一顆粒子 skin 很大，所有葉節點的外擴都會變大，所以劇本二的群聚分布下，八元樹重建次數較少，但距離比對次數與偵測時間比均勻網格多；均勻分布時則是八元樹較快。
- 「上一幀」保存的幀數有上限（約 150 萬個數字），劇本二（6,000 顆）約可退 19 幀。
- 觀眾視角的滑鼠鎖定需要瀏覽器支援 Pointer Lock，建議使用 Chrome。
